## What belongs in Git

Commit configuration, reviewed examples, documentation, the CLI version hint, and both `.terraform.lock.hcl` files. The lock file records provider dependencies and package checksums; it is not a Terraform state file.

The ignore rules exclude `.terraform/`, real `.tfvars` / `.tfvars.json`, real `.tfbackend` / `.tfbackend.json` files, state and state backups, saved plans, credentials, local tools, and environment files. Example files ending in `.example` remain trackable.

**Keep actual state and saved plans outside the checkout**, even though Git would ignore them. Ignore rules reduce accidental commits; they do not encrypt files, remove already tracked secrets, or prevent someone from explicitly force-adding a file. If a credential is exposed, remove its validity at the source rather than treating a Git deletion as sufficient recovery.

## Local checks for this milestone

No AWS login is required for the following checks. Install Terraform 1.17.1 first. Run these from the repository root in PowerShell. If it is not on PATH, set `$tf` to the absolute path of the verified executable.

```powershell
$tf = "terraform"
& $tf version
& $tf fmt -check -recursive infra

foreach ($root in @("infra/bootstrap", "infra/environments/dev")) {
    & $tf "-chdir=$root" init -backend=false -input=false -lockfile=readonly
    if ($LASTEXITCODE -ne 0) { throw "Dependency initialization failed: $root" }
    & $tf "-chdir=$root" validate
    if ($LASTEXITCODE -ne 0) { throw "Configuration validation failed: $root" }
}

& $tf -chdir=infra/bootstrap test
if ($LASTEXITCODE -ne 0) { throw "Mocked bootstrap tests failed." }

# Requires Python 3.9+ and PowerShell (pwsh or powershell on PATH).
# If discovery cannot find PowerShell, set this to its executable path:
$env:BOOTSTRAP_POWERSHELL = (Get-Process -Id $PID).Path
python -m unittest discover -s tests -v
if ($LASTEXITCODE -ne 0) { throw "Bootstrap helper tests failed." }
```

`init -backend=false` downloads / installs the pinned provider locally, but does not configure the local or S3 state backend. `validate` checks syntax and provider schemas without verifying deployment against live AWS resources. All native Terraform test runs use a fully mocked AWS provider and simulated plans; they never apply resources or call AWS. The helper tests use temporary directories and fixture IDs. Confirm the Python runner reports eight tests, rather than skips caused by a missing PowerShell executable. Internet access is needed for package downloads unless dependencies are cached. No CI workflow is introduced in this milestone.

See [Terraform init](https://developer.hashicorp.com/terraform/cli/commands/init) and [Terraform validate](https://developer.hashicorp.com/terraform/cli/commands/validate) for the limits of these checks. Do not infer that a passing validate confirms IAM permissions, quotas, AMI availability, or cost coverage.

The offline calculator remains available independently:

```sh
python scripts/estimate_costs.py
```

## Inputs and authentication

`aws_region` defaults to `us-east-2` and validates against that Region. `aws_profile` defaults to `devops-free`; it is a profile name, not a credential. Bootstrap also requires `expected_account_id` with no default. The tracked ID is a fixture only. Use the [external preparation helper](bootstrap.md#1-prepare-external-paths) with the verified project ID for future live operations. Keep actual inputs outside the checkout and never put access keys in them.

AWS service work in a later milestone must use the existing temporary-credential login flow, with any interactive sign-in completed by the human user. Never copy tokens, the AWS login cache, or CLI credential files into this repository. Local fmt, dependency initialization with the backend disabled, and validate do not need a renewed AWS session.

## State setup and deployment boundary

`dev/backend.tf` declares a partial S3 backend. Its example configuration deliberately contains a placeholder bucket and must not be used as a real initialization file. Before configuring it, create and verify the backend through the separately reviewed bootstrap procedure.

`bootstrap/backend.tf` explicitly declares a local backend with an external fallback path. Prefer absolute external paths from `prepare-bootstrap.ps1`; keep `TF_DATA_DIR` external for provisioning and migration too. See [the runbook](bootstrap.md) for protections and limitations, the required fresh cost/Region preflight, distinct state keys, recovery, and separate final cleanup.

The authorized bootstrap creation is complete, and read-only bootstrap review plans are available for verification. That approval does not authorize additional applies, `destroy`, `import`, state-changing refresh operations, backend migration, or other AWS changes. Dev still needs implementation. Use the local checks above for routine source validation.

## Updating dependencies later

Make updates deliberately: update `.terraform-version` and both exact CLI constraints, update both provider constraints, regenerate both lock files, and rerun local checks. Update the documented versions in the same change.

Generate cross-platform hashes with [terraform providers lock](https://developer.hashicorp.com/terraform/cli/commands/providers/lock) for each root:

```sh
terraform -chdir=infra/bootstrap providers lock -platform=windows_amd64 -platform=linux_amd64
terraform -chdir=infra/environments/dev providers lock -platform=windows_amd64 -platform=linux_amd64
```

Add other platforms when needed. The current lock files cover Windows AMD64 and Linux AMD64; they do not claim that this scaffold has been executed on Linux.
